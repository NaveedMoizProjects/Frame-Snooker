# Frame Snooker — How The Current Code Actually Works

This doc is generated by reading your actual scripts (not the original design doc, which
isn't in this project) — so it describes what the code *does today*, including a few
inconsistencies worth knowing about. Use it as a map when debugging.

## 1. The turn / shot state machine

State lives entirely in `GameManager`: `confirmMode`, `inputLocked`, `nextplay`,
`strikeRequested`.

```
FREE AIM
  └─ CueVisualController rotates the visual stick (mouse/touch drag)
  └─ Cue.GenerateAimPrediction() draws the aim/contact lines
        │
        ▼ player presses the on-screen Confirm button (GameManager.ConfirmButtonPressed)
CONFIRMED / AIM LOCKED   (confirmMode = true, inputLocked = true)
  └─ CueVisualController stops responding to drag (respectInputLock)
  └─ ShotPowerSlider becomes interactable (its Update() checks IsConfirmMode && isNextPlay())
        │
        ▼ player drags power slider and releases (IPointerUpHandler.OnPointerUp)
STRIKE REQUESTED
  └─ ShotPowerSlider calls SetStrikeForce(power) then RequestStrike()
  └─ RequestStrike() clears PottedThisShot + firstBallContacted for the new shot
  └─ Cue.Update() sees IsStrikeRequested && confirmed → pendingStrike = true
  └─ Cue.FixedUpdate() calls ApplyForceToCueBall() (impulse + optional spin torque)
        │
        ▼ balls moving
BALLS MOVING
  └─ GameManager.FixedUpdate() → CheckNextPlay() every physics step, checks every ball's
     rb.velocity.magnitude against moveThreshold / snapToZeroThreshold
        │
        ▼ all balls below threshold (transition moving → stopped)
ALL BALLS STOPPED → OnAllBallsStopped event fires, in this subscriber order (Awake()):
  1. unlock: confirmMode = false, inputLocked = false
  2. EvaluateFoul()          — reads state as it was BEFORE this shot
  3. EvaluateShotResult()    — mutates state for the NEXT shot (respot/advance colours)
        │
        ▼
back to FREE AIM
```

**Important ordering detail:** `EvaluateFoul` must run before `EvaluateShotResult`
because the latter mutates `targetState` / `currentTargetColour` for the *next* shot.
This is intentional (see the comment above `EvaluateShotResult`) — don't reorder the
subscriptions in `Awake()`.

## 2. Ball identity & the master ball list

- `BallIdentity` (one per ball GameObject) stores `BallType` (Cue/Red/Yellow/…/Black)
  and a `SpawnPosition` captured in `Awake()` — either the ball's scene start position,
  or a manually-set `manualSpawnPosition` if `useManualSpawnPosition` is checked.
- `GameManager.balls` (a manually-populated `List<Rigidbody>` in the Inspector) is the
  single source of truth for "every ball in the game." `GameManager.GetBalls()` exposes
  it so other scripts (currently just `BallRollingFriction`) don't need their own copy.
- **All 22 balls (cue + 15 reds + 6 colours) need both a `BallIdentity` component and a
  slot in `GameManager`'s `balls` list**, or scoring/foul logic silently can't see them
  (`GetBallType()` returns null → treated as "not a valid coloured ball" in several
  places).

## 3. Ball physics — three systems touching velocity

This is the part most likely to feel "off," because three separate systems currently
affect ball velocity:

| System | What it does | Where |
|---|---|---|
| `Rigidbody.drag` / `angularDrag` | Unity's built-in exponential decay | Set to `0.5f` each in `Cue.cs Start()` |
| `BallRollingFriction` | Custom slide→roll→stop model (see its own header comment) — explicitly built to *replace* the above | `FixedUpdate`, reads `GameManager.GetBalls()` |
| `CushionPhysicsMaterial` | Cushion bounce on contact | `OnCollisionEnter` on each cushion |

`BallRollingFriction`'s own comment says it exists specifically because
`Rigidbody.drag` "never reaches exact zero" and isn't physically grounded — but
`Cue.cs` still sets `drag = 0.5f` / `angularDrag = 0.5f` on the cue ball's Rigidbody at
`Start()`, which fights against it. **Recommend setting both to 0** in the `Cue`
component's Inspector fields (`Drag`, `Angular Drag`) so `BallRollingFriction` is the
only thing controlling deceleration. This likely contributes to inconsistent-feeling
rolling distance, separate from the cushion bug.

`CushionPhysicsMaterial` — see `docs/CUSHION_PHYSICS_FIX.md` for the specific bug that
was causing balls to stick to cushions, and the fix.

**Strike force pipeline:** `GameManager.baseStrikeForce` is the single tunable base
force (comment explicitly warns: keep `Cue.forceMultiplier` at `1` while tuning this,
adjust one at a time, not both). Final impulse = `baseStrikeForce * forceMultiplier`,
applied via `AddForce(..., ForceMode.Impulse)`. Spin torque (if
`applySpinTorque = true`) is a fixed `0.1 ×` fraction of that same impulse, around the
axis perpendicular to the strike direction.

## 4. Potting pipeline

```
Ball's collider enters a pocket trigger (PocketTrigger.OnTriggerEnter)
   → GameManager.OnBallPotted(rb)
        - cue ball: repositioned to cueBallRespawnPoint, stays active ("ball in hand")
        - any other ball: velocity zeroed, GameObject deactivated (pooled, not destroyed)
        - added to PottedThisShot list
        - OnBallPottedEvent fires (currently unused by any other script - hook point
          for SFX/crowd reactions later)
```

`PottedThisShot` is cleared at the *start* of each shot (`RequestStrike()`), not after
being read — so it always reflects "what happened in the shot in progress / just
finished," which is what `EvaluateFoul` / `EvaluateShotResult` both read from once
`OnAllBallsStopped` fires.

## 5. Cue ball contact tracking (for fouls)

`CueBallContactTracker` (on the cue ball only) reports the *first* rigidbody it
physically collides with each shot via `GameManager.ReportCueBallContact()`.
`firstBallContacted` is reset to `null` in `RequestStrike()` and only ever set once per
shot (subsequent contacts in the same shot are ignored). This is the sole input to the
foul table in `EvaluateFoul()` for "did they hit the right ball first."

Note: a cushion has no `Rigidbody`, so `collision.rigidbody == null` and cushion-only
contact correctly does **not** count as a ball contact.

## 6. Colour / Red target state machine

- `TargetBallState`: `Red` or `Colour`. Starts on `Red`.
- `NeedsColourNomination` is `true` exactly when: on `Colour` state, no colour chosen
  yet, **and** reds remain on the table. `GameManager.ConfirmButtonPressed()` refuses
  to lock aim while this is true.
- `ColourNominateButton` (one per colour button) calls
  `GameManager.OnColourNominated(colour)`, which sets `currentTargetColour` — but only
  while `targetState == Colour` and reds are still on the table (once reds are gone the
  fixed `ColourSequence` array drives it automatically, nomination is ignored).
- On a legal red pot (`EvaluateShotResult`), state flips `Red → Colour` and
  `currentTargetColour` resets to `null` (needs nominating again).
- On a colour pot (`ResolveColourPot`): if reds remain, the ball respots to its
  `BallIdentity.SpawnPosition` and state flips back to `Red`. If reds are gone, the
  ball stays potted and `AdvanceColourSequence()` moves to the next fixed colour.
- **Known gap, already flagged in the code's own comments:** if a red is potted as part
  of an otherwise-foul shot, `EvaluateShotResult` still flips to `Colour` state — the
  scoring itself is still correct (handled by `EvaluateFoul`), but this specific
  state-transition edge case doesn't fully match strict snooker rules. Left as-is
  intentionally; revisit only if you care about that edge case.

## 7. Foul evaluation (`EvaluateFoul`)

Single function, runs once per completed shot, decision table roughly:

- **On Red:** foul if cue ball potted, nothing hit, first contact wasn't a red, or any
  non-red ball was potted this shot. Otherwise legal, points = (reds potted × 1).
- **On Colour:** foul if cue ball potted, nothing hit, first contact wasn't the
  nominated/sequence colour, or anything other than exactly that one colour was potted.
  Otherwise legal, points = that colour's value.
- All foul point values are floored at `Math.Max(4, ...)` per standard snooker minimum
  foul value.
- Legal + 0 points (a miss with nothing potted) → turn passes, no score.
- Legal + points → `AwardPoints(currentPlayerIndex, points)` (turn does **not** pass on
  a legal pot — player continues).
- Foul → `AwardPoints(opponentIndex, points)` + `PassTurn()` always.

## 8. UI wiring

- `ScoreboardUI` — subscribes to `OnScoreChanged` / `OnTurnChanged`, purely reactive,
  manual `TextMeshProUGUI` references (no runtime building).
- `ColourNominationUI` — **check whether this is still in use.** `GameManager`'s own
  `Awake()` comment says: *"This replaces ColourNominationUI entirely — GameManager
  just toggles the panel GameObject directly."* `GameManager` has its own
  `colourNominationPanel` field + `RefreshColourNominationPanel()` wired to
  `OnTargetChanged`. If `ColourNominationUI` is *also* still active in the scene on a
  Canvas, you have **two independent nomination UIs** both listening to the same event
  and both building/toggling their own panel — likely source of duplicated or
  conflicting-looking colour-nomination UI. Recommend disabling/removing the
  `ColourNominationUI` component from the scene if `GameManager`'s manual panel is the
  one you're actually using (check `Hierarchy → CanvasGameObject` for both).
- `ColourNominateButton` — one per colour button, straightforward passthrough to
  `GameManager.OnColourNominated`.
- `ShotPowerSlider` — only interactable in confirm mode + when balls aren't moving;
  fires the shot on pointer-up at whatever power the slider was left at.
- `CameraSwitching` — three Cinemachine cameras (top-down / third-person /
  first-person FreeLook), keyboard shortcuts 1/2/3, plus single-touch drag control of
  the FreeLook camera's axes on mobile when it's active.

## 9. Quick reference — script responsibilities

| Script | Attached to | Owns |
|---|---|---|
| `GameManager` | one object (singleton) | all game state, turn flow, scoring, fouls |
| `BallIdentity` | every ball | type + respawn spot |
| `Cue` | cue controller object | aim prediction, strike impulse |
| `CueVisualController` | visual stick object | stick position/rotation from input |
| `CueBallContactTracker` | cue ball only | first-contact reporting |
| `BallRollingFriction` | any one object (e.g. GameManager) | slide/roll/stop friction model |
| `CushionPhysicsMaterial` | each cushion | rebound off rails |
| `PocketTrigger` | each of 6 pockets | pot detection → hands off to GameManager |
| `ColourNominateButton` | each colour button | nomination input |
| `ColourNominationUI` *(check if still needed — see §8)* | Canvas | legacy runtime-built nomination panel |
| `ScoreboardUI` | Canvas | score/turn display |
| `ShotPowerSlider` | power slider | power input + firing the shot |
| `CameraSwitching` | camera rig object | camera mode switching |
